# AGENTS.md

Single-file Python project: `harnless.py` — a minimal CLI agent harness that talks to a local llama-server (OpenAI-compatible API) and exposes file/shell tools (bash on POSIX, PowerShell on Windows). Stdlib only; no dependencies, no venv, no build step.

## Requirements

- A running LLM server for the agent to talk to. Default endpoint is `http://127.0.0.1:11434/v1/chat/completions` (`API_URL` in `harnless.py:14`), overridable via `--api-url`. Tests (`tests.py`) don't need a server.

## Commands

- Interactive: `python harnless.py` (chat REPL; typing `/` on an empty line opens a command menu (up/down move, enter select, esc cancel — a selection fills the line, a cancel keeps the `/`), `/new` clears session history and starts a new session log, `/clear-screen` clears the terminal, `/sessions` lists the recorded session logs and `/resume <id>` continues one (`/resume` with no argument prints the list), `/tools` opens an interactive tool menu (up/down move, space toggle, enter apply, esc cancel; mcp tools are grouped under their server entry, collapsed by default — `+`/`=` expands the group under the cursor, `-` collapses it, and up/down skip collapsed rows — where space toggles all of the server's tools at once (any off → all on, else all off) while individual tools can be toggled on their own rows when expanded) and `/tools <name>` toggles a tool on/off (`/tools mcp:<server>` toggles all of a server's tools), `/auto-send on|off` switches the send key (on = Enter submits, the default; off = Enter inserts a newline and Ctrl+Enter submits), `/compact` replaces this session's older turns with a handoff note now, `/auto-compact on|off|threshold N` configures automatic compaction, `/exit` quits)
- One-shot: `python harnless.py --prompt "task"` (exits with the agent's exit code)
- Session log (on by default): every conversation is journaled as JSON Lines under `SESSION_DIR` (`.harnless/sessions`, `HARNLESS_SESSIONS_DIR`, or `--sessions-dir DIR`) — `<session-id>.jsonl` for the top-level conversation and `<session-id>.<chain>.jsonl` per sub-agent run, where the dotted chain id is the delegation path (`1`, `2`, `1.1` …; `tool_task` allocates it via `AGENT_LOG_ID` + `SUBAGENT_CHILDREN`, saved/restored around the run like `OUTPUT_INDENT`). Records (`_session_append`, journal section after the output caps): `session` header (mode/version/model/cwd/api_url, plus `depth`/`subagent_id`/`parent_log`/`task` for a sub-agent), `message` (the message dict as replayed to the API — envelope keys `seq`/`ts`/`chars` are added **after** the message's own keys so a server key can never shadow one), `usage` (per model call: message count + server-reported tokens; written by `_record_usage`), `compact` (what context compaction replaced: `replaced` seq range, `dropped`/`kept`, `summary_seq`, `summary` model/fallback + `summary_error`, `pruned_chars`, `window`/`used_tokens`/`turn_tokens`/`token_scale`/`request_tokens`/`keep_tokens`), and `end` (how a sub-agent's run ended); `resume`/`cleared` mark continuations. Hook points: `main()` (system + user messages, `start_session()`, `/new` = a new log), `_agent_loop` (assistant, tool results incl. batch-skip/interrupt answers, step-limit prompt; `conv_key = conv_id or id(messages)` — the same key `_record_usage` and `SESSION_FILES` use), `_todo_reminder(messages, conv_key)`, `tool_task` (opens the child log, journals its system+task messages, frees `SESSION_FILES`/`SESSION_SEQ`/`SUBAGENT_CHILDREN` in its `finally`). `seq` counts from 0 per conversation and **continues** across a resume — it is the stable message id compaction names replaced turns with, and the id the `sessions` tool reads those turns back by. Base64 `image_url` parts are elided to a note (real size kept in `chars`, `SESSION_URL_KEEP`). `_session_append` never breaks a session: an `OSError`/`TypeError` calls `_session_disable` (one warning, then `SESSION_LOG = False`). Off with `--no-session-log`.
- Resume: `--resume SPEC` / `--resume-last [N]` (startup; `--resume-last` with no `--resume` continues the newest session) and `/resume <id>` (REPL) rebuild a conversation from a journal via `resume_session(spec, keep)` → `_session_resolve` (`latest`, a session id, a `"<id>.<chain>"` sub-agent log, or a path) → `_session_read` → `_session_rebuild`. Rebuild drops the envelope keys (`_SESSION_META_KEYS`) and every recorded `system` message (the resumed run writes its own, with the current AGENTS.md/memory), drops tool answers whose call is gone and assistant messages with neither content nor tool_calls (servers reject both), and answers any call the log left dangling with `SESSION_UNANSWERED_NOTE`. `--resume-last [N]` cuts the **records** before rebuilding, so a cut inside a tool-call batch cannot leave an orphan answer. On its own (no `--resume`) `--resume-last` is the shorthand for "continue where I left off": `_resume_target(resume, resume_last) -> (spec, keep, implied)` supplies spec `latest`, `implied` being what makes a miss there soft (warn `… — starting a new session`, then `start_session`) where a session id the user named still fails the run with exit 1. The resumed run keeps **appending to the same file** (`_session_continue` re-points `SESSION_FILES[MAIN_CONV_ID]` and continues its `seq`) and the restored messages are **not re-journaled** — re-recording them would double the log at every resume. `/sessions` and `format_sessions(limit)` list what is recorded (newest first; `latest` means a top-level log, not a sub-agent log).
- Resume echo (v1.7.2): a resume in the **REPL** also replays the tail of the journal it restored, so you can see where you left off — `resume_session(spec, keep, mode, echo)` prints the note itself and then `replay_session_tail(records, echo, SESSION_ID)`; `main()` passes `echo=RESUME_TAIL_ITEMS` for both the startup resume and `/resume <id>`, and `0` for a one-shot run (`--prompt` has nobody standing there, and with `echo=0` `resume_session` prints nothing so the caller prints the note as before). `_session_tail(records, items)` picks a **contiguous** slice — the last `RESUME_TAIL_ITEMS` *speaking* turns (`user`/`assistant`) extended over the tool calls and answers between them, cut to the last `RESUME_TAIL_RECORDS` records so a tool-heavy turn cannot flood the screen, except that the window always keeps the last speaking turn (a log ending on a long run of answers is exactly what the session looked like). It prints through the same printers the loop used — `print_user`, `print_reasoning`, `print_assistant`, `print_tool_call`, `print_tool_result` (extracted from `_agent_loop`, which now calls them too, so a replay cannot drift from what the session showed; `TOOL_ARG_ECHO` = 200 chars of arguments and `TOOL_RESULT_ECHO` = 500 chars of a result are the same caps either way), each tool call followed by the answer the log recorded for it, in order. A reply is shown whole; a thinking block is capped at `RESUME_TAIL_CHARS` with a `…[+N chars in the session log]` note. `_session_injected_turn` hides what the user never saw as their own line: a `system` record, a `_todo_reminder` (matched by `TODO_REMINDER_HEADER`) and a compaction note (matched by `COMPACT_SUMMARY_HEADER`). Nothing is re-journaled — the replay reads records, it does not feed them back into the conversation.
- Flags: `--api-url` (OpenAI-compatible API URL; accepts either a base URL like `https://openrouter.ai/api/v1` or a full `.../chat/completions` endpoint — a base URL gets `/chat/completions` appended; default `http://127.0.0.1:11434/v1/chat/completions`), `--api-key` (sent as `Authorization: Bearer <key>`; omit for unauthenticated local servers), `--model` (name sent in the request; llama-server ignores it), `--system-prompt` (replaces built-in), `--temperature` (sampling temperature; default `1.0`), `--max-subagents` (max sub-agent nesting depth for the `task` tool; default `2`, clamped to 0–`SUBAGENT_DEPTH_CEILING` = 10; `0` disables sub-agents), `--max-subagent-steps` (model turns a single sub-agent may take before its run is stopped; default `40`, `0` = unlimited; top-level agents are never capped), `--shell` (shell for `run_shell` on Windows: `auto` (pwsh → powershell → cmd), or force `pwsh` / `powershell` / `cmd`; default `auto`, ignored off-Windows), `--context-window` (model context window size in tokens, shown as a percentage in `/status`; if omitted, probed best-effort from the API's `/models` endpoint — `context_length` (OpenAI/OpenRouter) or `meta.n_ctx` (llama.cpp) — and hidden if the probe fails), `--no-auto-compact` (no automatic compaction; a rejected-for-size prompt then ends the run with `CONTEXT_OVERFLOW_CODE` = 3, `/compact` still works), `--compact-threshold PCT` (auto-compact once the conversation reaches this percentage of the window; default `COMPACT_THRESHOLD_PCT` = 85, clamped to `COMPACT_THRESHOLD_CEILING` = 99), `--sessions-dir` (where session logs are written; default `.harnless/sessions` or `HARNLESS_SESSIONS_DIR`), `--no-session-log` (do not journal the session), `--resume` (continue a recorded session: a session id, a `"<id>.<chain>"` sub-agent log, `latest`, or a path to a `.jsonl`), `--resume-last [N]` (`nargs="?"`, `default=None` so *absent* differs from `0`: absent = no resume; given = resume the **newest** session keeping all its records, or only the last N when N is given, clamped to `SESSION_KEEP_CEILING` = 10_000; with `--resume` it just trims that session; resolved by `_resume_target`), `--version` (print `harnless <version>` and exit; the version also appears in the REPL/one-shot startup banners)
- MCP servers (tools only): `~/.harnless/mcp.json` is auto-loaded at startup if present (same JSON format), then `--mcp-config FILE` (repeatable; JSON `{"mcpServers": {...}}` or a bare `{...}`), `--mcp-stdio 'NAME:COMMAND ARGS...'`, `--mcp-http 'NAME=URL'` — later definitions win on duplicate server names. `${VAR}` in a config is expanded from the environment. A server entry may set `"enabled": false` (enabled by default when the key is absent) to skip connecting it at startup — such servers are kept pending and can be enabled from the `/tools` menu (a second section lists them; toggling one on and pressing enter connects it and registers its tools) and are shown under `mcp servers (disabled)` in `/status`. Once connected, a server's tools appear grouped under an `mcp: <server>` row in the `/tools` menu (and in the non-TTY `/tools` listing via `format_tools`); the server row's checkbox shows `x`/` `/`-` for all-on/all-off/mixed. A server that fails to connect/list tools is skipped with a warning. On Windows, a stdio `command` that resolves (via `shutil.which`) to a `.cmd`/`.bat` shim (npx, npm, uvx, …) is spawned with `shell=True` — `CreateProcess` can't launch shims directly (`WinError 2`).
- `AGENTS.md` in the working directory (case-insensitive) is auto-loaded and appended to the system prompt in all modes.
- Interactive-mode input history is persisted to `~/.harnless_history` (last 1000 entries, one per line); path overridable via the `HARNLESS_HISTORY` env var.
- Line editor rendering (`_edit_cur`, `_edit_rows`, `_edit_phys_pos`, `_edit_line.render`): the caret model is the terminal's **pending wrap** — measured on Windows with `CONOUT$` + `GetConsoleScreenBufferInfo`, a run that exactly fills a row leaves the caret in that row's **last** column and the next row is entered only by the next printable character, so a character position landing on a wrap boundary is the last cell of the row *before* it (not col 0 of the row after), and `ESC[nA/B/C/D` / `\r` act on that cell. `render()` tracks `prev_rows` (rows the last render painted) and `prev_cur_row` (the row the caret ended on) and walks back from the **caret** — not from the previous text's end row; that mismatch made a wrapped block creep one row per keystroke (and duplicate its tail rows) as soon as the caret moved above the block's last row. Buffer newlines are written as explicit `\r\n` (a bare LF only moves down in raw mode). Every exit path (Enter, Ctrl+Enter, Ctrl+D, Ctrl+C) goes through `commit()`: redraw the line from its first row, then `\r\n`, so the cursor lands on the fresh row below the block instead of leaving input rows behind. `tests.py` replays every render through `_MiniTerm` (same pending-wrap model) and asserts the block stays anchored with no stale rows — change the model in either side and those tests fail.
- Multi-line REPL input and send modes: Ctrl+J inserts a newline into the current line. `AUTO_SEND` (default `True`) means Enter submits; `/auto-send off` switches to Ctrl+Enter send, where Enter inserts a newline and Ctrl+Enter (or Ctrl+D on a non-empty line) submits. The key iterators yield a `newline` token for `\n` (Ctrl+J), `enter` for `\r`, and `ctrl_enter` when Ctrl+Enter is detectable — on Windows via `GetAsyncKeyState` (`_windows_ctrl_held`, best-effort: msvcrt can't distinguish Enter from Ctrl+Enter, both are `\r`), on POSIX via terminal escape sequences (`\e[13;5u` kitty protocol, `\e[27;5;13~` xterm modifyOtherKeys, `\e\r` tmux-style binding; plain `\r` is indistinguishable, so Ctrl+D is the reliable send key there). `_edit_line` inserts `\n` at the cursor and `render()` redraws multi-line input with ANSI cursor moves + `\x1b[2K` (no newlines, so the screen never scrolls). Up/down first move the caret line-by-line within a multi-line buffer (column preserved, clamped to the target line) instead of jumping to history; from the first line, up recalls the previous history entry while saving the current line as a draft — the first down restores it (buffer and caret), and editing a recalled entry discards the draft so later downs walk history forward. The `/` command menu and `/tools` menu accept `ctrl_enter` as select/apply alongside Enter. The non-TTY `input()` fallback stays line-based.
- Streaming interrupt: in the REPL, pressing ESC twice within 2 s while the LLM is streaming cancels the generation (a lone ESC prints a hint) — it also works while the context is being sent, aborting the upload itself. The partial assistant message is kept in the conversation (any half-formed `tool_calls` are stripped; partials left without `content` — e.g. interrupted mid-thinking — are dropped, since servers reject assistant messages with neither content nor tool_calls) and the agent returns to the prompt. Works while sub-agents stream too, and it stops the **whole delegation chain**: a sub-agent's `_agent_loop` re-raises `StreamInterrupted` instead of returning 0, `tool_task` converts it into `SubagentInterrupted` (carrying `SUBAGENT_INTERRUPT_PREFIX` + whatever the sub-agent had managed to say, wrapped once rather than once per level), `execute_tool` re-raises it instead of reporting it as a tool error, and the top-level agent ends the turn and returns to the prompt. In the interrupted tool batch the aborted call gets that bubbled-up note as its tool result and every remaining call in the batch gets `interrupted by user`, so no `tool_calls` are ever left unanswered (servers reject those).
- Tests: `python tests.py` — stdlib unittest, no pytest. Must run from repo root; uses a temp `./_test_tmp` dir (cleaned up); exit code 1 on failure. Sub-agent tests drive the **real** `run_agent`/`_agent_loop` with a scripted `stream_once` (`TestSubagents._scripted`, which keys the script on `h._AGENT_DEPTH`): faking `run_agent` hides depth plumbing, a scripted stream must return `streamed=True` (`False` makes `run_agent` fall back to `chat()` — a live request to whatever server is listening on 127.0.0.1:11434), and `TestSubagents` patches `chat` to raise so that can never happen by accident. Runs green **on Linux too** — check it with the build container: `podman run --rm -v "${PWD}:/src:rw" -w /src localhost/harnless-builder python tests.py` (that is how `run_shell`'s POSIX path — `start_new_session=True` + `os.killpg` — is exercised, since Windows uses `taskkill /T`). Tests that assert Windows-only *logic* must fake the platform (`TestResolveShell._fake_windows` patches `h.os.name` to `"nt"`, because `_resolve_shell` short-circuits off Windows) rather than being skipped or silently passing on the wrong OS. Inside the container, repo git commands need `git -c safe.directory=/src …` (mounted Windows files look like a different owner). `TestSessionLog` drives the same real loop for the journal and the resume path: it patches `_session_new_id` for predictable file names and points `SESSION_DIR` at `./_test_tmp/sessions` (CLI-level tests pass `--sessions-dir` into that temp dir, so the repo's own `.harnless/sessions` stays free of test logs).

## Notes

- `tests.py` imports the module directly (`import harnless`).
- Tools are defined once in the `TOOLS` dict (`harnless.py:961`): each entry is `(OpenAI schema, handler)`. `OPENAI_TOOLS`/`DISPATCH` are derived from it — add new tools there. `OPENAI_TOOLS_INTERACTIVE` (same minus `exit`) is sent to the API in interactive mode; `exit` stays one-shot only.
- `grep` and `glob` **skip what a `.gitignore` would hide** (the rules git applies in that directory, with no `git` subprocess involved). The agent opts out with `respect_gitignore: false`, and an ignored file it names as `path` is searched anyway. Full semantics, the invariants, and which test guards them: the `Search filtering (v1.8.0)` bullet near the end of this file — which sits past `AGENTS_MD_LIMIT`, so this line is the part the model actually sees.
- `run_shell` shell: on Windows, `_resolve_shell` (`harnless.py`) picks `pwsh` (PowerShell 7+) → `powershell.exe` (5.1) → `cmd.exe` (via `shell=True`), overridable with `--shell`. It spawns the shell directly with `-NoProfile -NonInteractive -Command` (no `shell=True`), prepends `[Console]::OutputEncoding=[Text.Encoding]::UTF8; ` on **all** PowerShell (both 5.1 and pwsh 7 may emit the ANSI code page on *redirected* stdout — e.g. cp1256 on an Arabic-locale Windows with pwsh 7.6, which lost all output until the prefix was applied to pwsh too), decodes output as UTF-8 with `errors='replace'` (a stray non-UTF-8 byte from a native command degrades to U+FFFD instead of crashing the reader thread and wiping the whole output), and appends `; exit $LASTEXITCODE` because PowerShell `-Command` maps **any** non-zero native exit code to `1` (the real code is only recoverable via `$LASTEXITCODE`). Non-Windows always uses `shell=True` (sh). The `run_shell` tool description (`SHELL_NOTE`) tells the model to use PowerShell syntax on Windows.
 - `run_shell` timeouts (v1.5.2): spawned with `Popen` + `communicate(timeout=…)` instead of `subprocess.run(timeout=…)`. `run()` killed only the **direct child** — the shell wrapper — and then drained the pipes with **no deadline of its own**, so a surviving grandchild (a test runner, compiler, dev server) that still held the inherited stdout handles made the harness wait for *it*: a reported 3s timeout took 25s, and the runaway needed a human to kill it. `_kill_tree` now kills the whole tree — `taskkill /PID <pid> /T /F` (`_TASKKILL`, resolved once at import, `CREATE_NO_WINDOW`) on Windows, `os.killpg(SIGKILL)` on POSIX (the spawn there sets `start_new_session=True`, which is why the group is ours) — falling back to plain `proc.kill()` if the tree killer is missing. `_drain_killed` then collects what was buffered (Windows keeps it in the reader threads until `communicate()` runs, so the `TimeoutExpired` fields are empty there; POSIX fills them) under `KILL_DRAIN_TIMEOUT`, closing the pipes if even the drain stalls, and reaps with a bounded `wait()`. The arg is read by `_shell_timeout` (`SHELL_TIMEOUT_DEFAULT` 120, `SHELL_TIMEOUT_MIN` 1, `SHELL_TIMEOUT_CEILING` 3600, bad values rejected with an error as `fetch_url` does). A timed-out call returns `error: command timed out after Ns — it was killed, along with everything it started` plus a `[partial output]` block (`_truncate`d at `max_output`). `TestRunShell.test_timeout_kills_the_whole_process_tree` spawns a grandchild that drops a marker if it outlives the timeout and also asserts the call came back promptly (it costs ~11s of suite time; verified by hand — `h._TASKKILL = []` restores the old wrapper-only kill, and the marker then appears with a 25s drain).
- Output capping (v1.2.0): two layers. Model-facing limit args — `grep.limit`, `glob.limit`, `list_dir.limit`, `read_file.max_chars`, `run_shell.max_output`, `fetch_url.max_chars` — are read by `_limit_arg` and clamped to `[1, ceiling]`; defaults/ceilings are the `*_LIMIT` constants in the constants block near `harnless.py:49`. `TOOL_RESULT_LIMIT` (60k) is the final backstop in `execute_tool` and must stay **above** every per-tool cap, otherwise a tool that already trimmed gets a second note (`test_cap_constants_are_ordered` guards the ordering). All truncation goes through `_truncate` / `_cap_count` / `_cap_note` (the "output caps" section above the tools) which append `\n... [truncated: <stat>; <recovery hint>]` — keep that one format so both tests and the model can rely on it. `grep` additionally clips every matched line at `GREP_LINE_LIMIT` (`_clip_line`, kills minified-file megadumps) and caps total output at `GREP_TEXT_LIMIT`. Paths that were uncapped before are now capped: `task`'s sub-agent summary, `_mcp_content_to_text` (incl. `structuredContent`), `_todo_block` (tool output + `_todo_reminder`; `_todo_render`/`_todo_save` stay uncapped so `.harnless/todo.md` keeps the full list), `tool_memory` list + `load_memory` (this block feeds every system prompt), and `load_agents_md`.
- State tools: `todo` (in-memory list persisted to `.harnless/todo.md`; after each tool batch, `_todo_reminder` re-injects a reminder (as a **user** message, not system — some templates like Qwen forbid system messages anywhere but the first position) with the current list into the conversation when it changes — `TODO_LAST_INJECTED` is saved/restored around sub-agent runs so the parent sees sub-agent edits) and `memory` (persistent notes in `.harnless/memory.md` (project) and `~/.harnless/memory.md` (global); one-line pitfall notes belong here too, prefixed `gotcha: ` — the separate `gotcha` tool and `.harnless/gotchas.md` were removed in v1.1.0). Memory is loaded into the system prompt at startup via `_context_additions` (also for sub-agents); the todo list is loaded at startup via `_todo_load`.
 - Session journal (v1.6.0) invariants: a conversation is journaled only if it is registered in `SESSION_FILES`, keyed `conv_id if conv_id is not None else id(messages)` — exactly how `_record_usage` keys usage — so a conversation with no opened log (a test driving `run_agent`, `--no-session-log`, a `task` call refused by the depth guard) writes nothing, and `tool_task` pops that key in its `finally` alongside `USAGE_BY_CONV` so an `id()` fallback can never land on a finished sub-agent's file. Each message is journaled **once**, when it enters the conversation (not per request), because the log has to survive later trimming of the live conversation: `seq` is the stable message id compaction names replaced turns with: `SESSION_MSG_SEQ[key]` keeps each message's seq **positionally** beside the conversation it describes (`None` for a message a rebuild invented, which has no record of its own), so `_session_span` can report the exact range a `compact` record replaced — and because it is positional, anything inserted at the *front* of a conversation (a resumed run's system prompt) must go through `_session_prepend`, which moves the just-appended seq into the slot the message actually occupies; `compact_messages` rewrites the same slice of that list when it swaps `[start:cut]` for the note. `_session_open` **starts** (never continues) its file — a new run owns it, so a log stays gapless with one header — and `_session_continue` is the only way to append to a log that already exists. Restored messages are never re-journaled and `_session_rebuild` drops every recorded `system` message, so a resumed conversation always starts with exactly one, current system message.
 - Context compaction (v1.7.0): `compact_messages(messages, conv_key, model, reason, interactive)` replaces `messages[start:cut]` (`start = _system_prefix`, so system prompts never go) with one **user** message (the `_todo_reminder` reason: some chat templates reject a system message anywhere but first) marked `COMPACT_SUMMARY_HEADER`, holding the model's note truncated to `COMPACT_SUMMARY_LIMIT` plus `_transcript_note`, which names the journal and the seq range the note stands for. The note comes from `chat(..., send_tools=False, conv_id=throwaway)` under `COMPACT_SUMMARY_PROMPT`; that throwaway conv_id is popped from `USAGE_BY_CONV` in a `finally` so a summarising request never masquerades as the agent's usage and nothing of its scaffolding is journaled. Refusals: fewer than `COMPACT_MIN_MESSAGES` messages, or nothing older than the verbatim tail — a refusal writes no `compact` record. The tail: `COMPACT_KEEP_TOKENS_PCT` sizes it, `COMPACT_KEEP_MIN_MESSAGES` floors it (`_compact_cut` compares a running cost against the budget, then applies the floor as `cut = min(cut, len - MIN)`, so the floor only ever *lowers* an over-eager cut, never raises a budget that covers everything), then the cut is nudged off a tool answer so a call batch is never split (`_batches_intact` is the test invariant). Tokens: `_msg_tokens` (content + reasoning + tool arguments, /4), `_turn_tokens` (**only** the turns — what compaction can act on; tool schemas and the system prompt are `estimate_context_tokens`' business, and an overflow caused by that fixed overhead is the reactive trigger's, which prints "compaction cannot help" instead of cutting turns that were never the problem), `_context_tokens_used` (server-reported `prompt_tokens` when known, else `_turn_tokens`), `_token_scale` = reported / estimated so `keep_tokens` and the per-turn costs are compared in the server's units — a reported 18k against a 4k-looking conversation cuts, an estimate-only conversation that fits its tail budget refuses. Room is made twice: `_compact_prune` (keep head+tail of `COMPACT_TOOL_RESULT_KEEP` per oversized tool result, `COMPACT_PRUNE_TOOL_RESULTS`) and `_compact_tail_prune` (`COMPACT_DROP_REASONING`: only the last assistant reply's reasoning can still shape what the agent does) shrink what is about to go *and* what stays; the sum is recorded as `pruned_chars`. The summarising request reads the newest slice of the head that fits `window - COMPACT_SUMMARY_LIMIT//4` (`_fit_head`, trimmed from the old end; `COMPACT_SUMMARY_TRIMS` halvings while `ContextOverflow` persists); if it still fails, `COMPACT_FALLBACK_NOTE` stands in and the record says `summary: "fallback"` + `summary_error` — the turns still go, because dropping them is what made the room. Triggers: `_compact_if_needed` (called in `_agent_loop` **before** each request; needs `AUTO_COMPACT` and `CONTEXT_WINDOW > 0`; a refusal is warned about **once** per conversation via `COMPACT_STATS[key]["warned"]`) and `_recover_overflow` (`ContextOverflow`, raised by `chat`/`stream_chat` when `_context_overflow_reason` matches `_CONTEXT_OVERFLOW_RE` on a `_CONTEXT_OVERFLOW_STATUS` status, prints the server's own wording, compacts, retries) — identical on the streaming and the non-streaming fallback path: still too big after `COMPACT_MAX_ATTEMPTS` ends the run with `CONTEXT_OVERFLOW_CODE` = 3 plus `_transcript_hint`. `compact_messages` pops `USAGE_BY_CONV[conv_key]` (the old count described the pre-cut conversation; leaving it would compact again next turn) and records `token_scale`/`turn_tokens`/`request_tokens` so a reader can re-derive the cut. A sub-agent compacts its own run in its own log. The `sessions` tool (`tool_sessions`: `list` / `read` / `spans`, `SESSION_READ_LIMIT`, `SESSION_RECORD_CHARS`, `_session_record_line`, `_session_read(path, kinds=("message", "compact"))`) reads the replaced turns back by seq and prints a `compact` record as the gap it made.
 - Sub-agents: the built-in `task` tool (`tool_task`) delegates a self-contained task to a nested `run_agent` with a fresh context (sub-agent system prompt + AGENTS.md, full one-shot tool set). It returns the sub-agent's exit code + final summary as the tool result. Depth is tracked in `_AGENT_DEPTH` and capped at `MAX_SUBAGENT_DEPTH` (`--max-subagents`, default 2, clamped to 0–`SUBAGENT_DEPTH_CEILING` = 10; `0` disables sub-agents); sub-agents can delegate further until the cap, and a call that would exceed it is refused with a message naming the cap and the level that call would have been at. **`_AGENT_DEPTH` is scoped to each `run_agent` call**: `run_agent` is a thin wrapper that sets it to its `depth` argument and restores the previous value in a `finally` (`_agent_loop` holds the loop itself) — without the restore, depth only ratchets upward inside one turn, so after a run nested to level 2 every later `task` call in the same turn (top-level ones included) was wrongly refused with 'sub-agent depth limit reached' (bug fixed in 1.4.5; the REPL masked it because each new user turn re-enters at depth 0). Runaway guard: `_agent_loop` counts model turns for **sub-agents only** and raises `SubagentStepLimit` past `SUBAGENT_STEP_LIMIT` (`--max-subagent-steps`, default 40, 0 = off); `tool_task` catches it and reports `exit code: SUBAGENT_STEP_LIMIT_CODE` (4) + "reached its step limit … this summary may be incomplete" (a signal rather than a return code, so it can't be confused with a code the sub-agent's own `exit` call chose); top-level agents are never capped, since the user steers them (and can double-ESC them). Sub-agent output is printed live, indented 2 spaces per level via `OUTPUT_INDENT`. `run_agent` returns the `exit` tool's code instead of calling `sys.exit` (the one-shot path in `main` does `sys.exit(run_agent(...))`), which is what lets a sub-agent's `exit` end only the sub-loop. Delegation is actively encouraged in prompts: the `task` tool description and a system-prompt paragraph nudge the model to delegate context-heavy work (codebase exploration, research to create plans, "how does X work" questions) so the parent context only receives the final summary; `SUBAGENT_NOTE` gives the sub-agent a summary contract (self-contained, key findings with file:line references, aim under 50 lines unless the task asks for more).
 - Summary hand-off (v1.5.1 — the loophole that made sub-agents look useless): harvesting used to be "the last assistant message with content", so a sub-agent that put its summary in `exit`'s `message` arg (which the `exit` schema advertises), ended on a tool-call-only turn, or wrote only `reasoning_content` came back to the parent as a bare `exit code: 0` — indistinguishable from "found nothing", which is why the parent redid the work. `tool_task` now harvests through `_closing_summary(messages, exit_note)`: the **longer** of the exit `message` and the last turn's content (a closing "done" cannot beat a real summary, and a summary sent via `exit` is not dropped), falling back to `reasoning_content` and then to earlier narration — salvaged sources are prefixed with `SALVAGED_SUMMARY_NOTE`; with nothing at all the result carries `NO_SUMMARY_NOTE` instead of reading like an empty success. `_agent_loop`'s exit handler records `e.message` in `EXIT_NOTE_BY_CONV[conv_id]` (keyed like `USAGE_BY_CONV`, popped in `tool_task`'s `finally`, sub-agents only) and answers the `exit` call plus every call queued behind it in the batch, as the interrupt path already did. Capped runs get one closing turn instead of stopping mid-tool-call: `_agent_loop` sets `closing_turn`, appends `STEP_LIMIT_CLOSE_PROMPT` as a user message, and raises `SubagentStepLimit` after that turn (limit + 1 turns total, always reported as capped so `tool_task` appends the "may be incomplete" note). `SUBAGENT_NOTE` and the `exit` description both state that the summary may go in the reply text or in `exit`'s `message`, and that nothing merely *printed* reaches the parent.
- MCP tools are discovered at startup (`register_mcp_tools`) and registered into `MCP_TOOLS`/`MCP_DISPATCH` (not `TOOLS`). They use raw names; a name colliding with a built-in tool or an earlier MCP server is skipped (built-ins win, then first server). MCP tools are external and bypass the `safe_resolve` sandbox.
- All tool file paths are relative to CWD and must stay inside it (`safe_resolve`, `harnless.py:224`); never weaken this. CWD itself may be a symlink/junction: `_cwd_roots()` (`harnless.py:176`) returns CWD plus its `realpath`, `_inside_cwd` checks containment case-insensitively (`os.path.normcase`) against both, and `grep`/`glob` print paths with `_rel_to_cwd` (`harnless.py:205`) so they stay CWD-relative (`src/main.py`, not `../../../real/src/main.py`). `safe_resolve` still returns the realpath, and a link *inside* CWD that points outside is still rejected.
- Glob patterns (`glob` tool, `grep` `file_pattern`) are compiled by `_glob_to_regex` (takes `case_sensitive`) against the whole CWD-relative path: `**/` matches zero or more directories (so `**/*.py` matches root-level files too), plain `*`/`?` cross `/`, and a pattern containing `[](){}|\^$` is used as a raw regex. The `grep`/`glob` `path` may be a **file** or a directory (`_iter_files`): a file is searched/matched directly (an explicit file is still filtered by `file_pattern`), and a missing path returns an explicit `error: path not found` instead of a silent no-match.
- Search case knobs (v1.5.0): `grep` and `glob` both take a model-facing `case_sensitive` boolean that **defaults to true** (exact-case matching, the Unix-grep default; behaviour changed from the always-case-insensitive `grep` of ≤1.4.x). `_case_flags` maps it to the `re` flags, `tool_grep` applies it to `pattern` **and** `file_pattern`, and `tool_glob` passes it to `_glob_to_regex` — so one knob covers both searches in a call. Read with `_bool_arg`, which also accepts the strings models often send (`"true"/"yes"/"1"` = on, `"false"/"no"/"0"` = off, anything else → the default), and an inline `(?i)` in a `grep` pattern still works. `TOOLS["grep"]`/`TOOLS["glob"]` expose the arg; keep `list_dir` without it.
 - Search filtering (v1.8.0): `grep`/`glob` do not see what git would not have shown in the same directory. The ignore engine is re-implemented in harnless — `_gitignore_glob_re` → `_gitignore_rules` (one file: `(regex, negate, dir_only, base)` list, **reversed** so the first match found is git's last matching line) → `_gitignore_file` / `_gitignore_ancestors` (the files **above** a searched directory, up to the nearest directory holding `.git`, capped at `GITIGNORE_ANCESTOR_SCAN`; a searched directory that has its own `.git` gets none) → `_ignore_view` (rules re-expressed as a path prefix per directory walked) → `_is_ignored`, all driven by `_iter_files(root, respect_gitignore=True, ignored)`. It is pure Python rather than `git check-ignore`/`git ls-files` so there is no subprocess, it works with no git installed and outside a repo, and it gives the same verdict on every platform — including the build container, where git refuses the mounted `/src`. Semantics (measured against `git check-ignore`, not just gitignore(5), which leaves `**` and precedence open): a bare pattern matches at any depth and matches directories too (which prunes their contents); a pattern holding a separator is anchored to its file's directory, a **trailing** slash alone does not anchor but restricts the rule to directories (so a file of that name survives); `**` crosses directories only as a whole path component (`**/`, trailing `/**`, bare `**`) — `a**/b` behaves like `a*/b`, and `dir/**` hides the contents but not `dir`; a nearer `.gitignore` outranks a shallower one; an ignored directory is pruned and a `!` written inside it cannot bring its contents back (git forbids that too); `*`/`?` never cross `/`, `[abc]`/`[!abc]` and backslash escapes work, an unclosed `[` or an unusable class (`[z-a]`) drops the pattern entirely; comments, blanks and unescaped trailing blanks are dropped; ignore matching is case-insensitive only where the filesystem is (`_ignore_case_flag`: `os.name == "nt"` → `re.IGNORECASE`, git's `core.ignorecase` default). `.git`/`node_modules`/`__pycache__` (`GITIGNORE_SKIP_NAMES`) are always skipped, opt-out included; `list_dir` is deliberately unfiltered, and `.git/info/exclude` + `core.excludesFile` are deliberately not read. The agent's knob is `respect_gitignore` (default true, read by `_bool_arg` so `"false"/"no"` work) on `TOOLS["grep"]`/`TOOLS["glob"]`; an ignored **file** the agent names as `path` is never judged (an ignored **directory** it names is not pruned, but the files under it still are), and when skipping is what emptied the answer `_gitignored_note` appends `... [N gitignored path(s) skipped per .gitignore; pass respect_gitignore:false to include them]` to `no matches` / `no files matched` (a capped answer carries its own truncation hint instead). `_iter_files` walks with `os.scandir` sorted by name (a deterministic grep order) and never descends into a linked directory, which is what `os.walk(followlinks=False)` used to guarantee. Tests: `TestGitignoreRules` (semantics line by line, `_is_ignored` judging one entry), `TestGitignoreTools` (`tool_grep`/`tool_glob`, the note text, the knob, ancestors), and `TestGitignoreAgainstGit` — fixture trees built **outside** the repo where git's own `git ls-files -z --others --exclude-standard` file set must equal `_iter_files`' output for the tree and for searches rooted inside it (global/system git config pinned off, `core.ignorecase` pinned to the platform's default; skipped when git is absent). That differential is the only real guard on the semantics — change the engine, run it on both platforms.
- `patch_file` supports an optional `offset`/`lines` region to disambiguate duplicate `old_string` matches; `write_file` with `offset` does line-range replace/insert (semantics covered by `tests.py` — run it after touching those functions).
- `/status` context usage: prefers the server-reported `usage.prompt_tokens` from the last API response (non-streaming responses include `usage`; streaming requests send `stream_options: {include_usage: true}` and the final SSE chunk carries it — `parse_sse_line` returns a `{"usage": ...}` marker for that chunk, which `stream_chat` records instead of yielding). Usage is stored per conversation in `USAGE_BY_CONV` keyed by an explicit conversation id (via `_record_usage`): the top-level conversation uses `MAIN_CONV_ID` (threaded from `main()` through `run_agent`/`stream_once`/`chat`/`stream_chat` and into `format_status`), and each sub-agent run gets a unique id from the `_NEXT_CONV_ID` counter that `tool_task` pops in a `finally` — `id(messages)` is a memory address and the freed sub-agent list's address gets recycled, so leaving entries behind would make `/status` resurrect stale sub-agent usage. Falls back to a chars/4 estimate (labeled "estimated") when no server usage is available yet (e.g. before the first response).
- Assistant output is styled by `MarkdownRenderer` (`harnless.py`), which supports headings, lists, blockquotes, fenced code, inline emphasis/code/links, and pipe tables (box-drawing borders, `:--`/`:-:`/`--:` alignment, inline styling in cells, terminal-width clamping). Tables are buffered whole before printing (a `|` line is held one line to test for a delimiter row); with colors disabled the raw Markdown passes through unchanged.
- Context progress: for large requests (estimated ≥ `CONTEXT_PROGRESS_THRESHOLD` = 30,000 tokens via `estimate_context_tokens`, chars/4 including the tool schemas — the same heuristic `/status` uses), `ContextProgress` shows a line on a daemon thread while waiting for the LLM's first token (streaming) or the full response (non-streaming `chat()` fallback). It appears `CONTEXT_PROGRESS_DELAY` (1 s) in, updates every 0.5 s, and is cleared (ANSI) when the wait ends. Two states: while the request body is uploading it shows `⏳ sending context… 45% (14.4k/32.4k tokens) 3s` (percent + tokens sent so far, from a `_UploadProgress` counter fed by `_progress_opener` — a urllib opener whose HTTP(S) connections send the body in `PROGRESS_CHUNK` pieces instead of one `sendall`); once uploaded it shows `⏳ waiting for first token (32.4k tokens) 12s`. Only active when stdout is a TTY (small contexts and non-TTY never start the thread, so tests/mocks of `urlopen` are unaffected). If the double-ESC hint prints below the line (`InterruptWatcher.on_hint` → `note_lines_below(2)`), the line freezes so a redraw can't clobber it, and `stop()` moves up to clear the right line.
- Streaming interrupt mechanics: `INTERRUPT_ENABLED` is set in `main()` for REPL sessions with a TTY stdin (one-shot mode never interrupts). Each streaming turn, `stream_once` starts an `InterruptWatcher` — a daemon thread running the polling key iterators (`_iter_keys_windows_poll`/`_iter_keys_posix_poll`, which poll `kbhit`/`select` so the thread can be stopped without a keypress). `check_double_esc` (pure, testable) detects two ESCs within `DOUBLE_ESC_WINDOW`; on trigger the watcher closes the response socket (`_response_socket` digs out the socket, trying both `resp.fp.fp.raw._sock` (older Pythons, `fp` is a `SocketFile`) and `resp.fp.raw._sock` (Python 3.14+, where `fp` is the `BufferedReader` directly)) so the main thread's blocked read unblocks — `close()`, not `shutdown()`, is what unblocks a pending `recv` on Windows — and sets `triggered`. The upload socket is attached too: `stream_chat` passes `watcher.attach_socket` as `_open_request`'s `on_socket`, and the counting connection reports it via `upload.on_socket` as soon as `connect()` completes, so a double ESC during the context send closes the socket mid-send and `stream_chat` swallows the resulting send error (the turn then ends via the same `StreamInterrupted` path). `stream_chat` checks `watcher.triggered` between deltas and swallows the resulting read error; `stream_once` finalizes the renderer, prints `(interrupted)`, and raises `StreamInterrupted` (carrying the partial message), which `run_agent` handles (strip `tool_calls`, append the partial only if it has `content`, return 0).
